# Occupancy Grid Navigation System

## Описание

Эта ветка содержит переработанную логику движения для прохождения строительной площадки и объезда машин, основанную на **Occupancy Grid + A\* Path Planning**.

### Почему Occupancy Grid?

Обычный реактивный алгоритм (секторы LiDAR) имеет проблему: **робот путает конусы с белыми линиями** и начинает от них поворачивать, что приводит к падению с трассы.

**Occupancy Grid решает эту проблему:**
- Робот не принимает решения по "объектам" (конус/линия), а строит карту свободного пространства
- Клетки за линиями помечаются как "запрещённые зоны" с очень высокой стоимостью
- Алгоритм A* ищет оптимальный путь через свободные клетки
- Даже если конус выглядит как линия, робот просто видит "занятое пространство" и планирует путь вокруг

## Архитектура системы

### Основные компоненты:

1. **Occupancy Grid (сетка занятости):**
   - Размер: 3м (длина) × 4м (ширина)
   - Разрешение: 5см на клетку
   - Обновляется каждые 100мс из данных LiDAR

2. **Типы клеток:**
   - `0` - свободная клетка
   - `10.0` - препятствие (конус, машина)
   - `100.0` - запрещённая зона (за линиями)

3. **A* Path Planning:**
   - Планирует путь от текущей позиции робота до цели
   - Учитывает стоимость клеток (избегает препятствий и запрещённых зон)
   - Использует эвристику Евклидова расстояния

4. **Pure Pursuit Controller:**
   - Следует по найденному пути
   - Адаптивное управление угловой скоростью
   - Переключение на следующую точку при достижении текущей

## Состояния робота

```
┌─────────────┐
│   NORMAL    │  ← Обычное движение по полосе
└──────┬──────┘
       │ Препятствие < 0.5м
       ▼
┌─────────────┐
│  PLANNING   │  ← Планирование пути A*
└──────┬──────┘
       │ Путь найден
       ▼
┌─────────────┐
│ FOLLOWING   │  ← Движение по пути
│    PATH     │
└──────┬──────┘
       │ Путь завершён
       ▼
┌─────────────┐
│  RETURNING  │  ← Возврат в центр полосы
└──────┬──────┘
       │ Отцентрирован
       └──────► NORMAL
```

## Преимущества перед старым алгоритмом

| Критерий | Старый (reactive) | Новый (Occupancy Grid) |
|----------|-------------------|------------------------|
| Путает конусы с линиями | ✗ Да | ✓ Нет |
| Работает с любыми формами | ✗ Плохо | ✓ Отлично |
| Проезжает туннели | ✓ Да | ✓ Да |
| Учитывает линии | ✓ Частично | ✓ Полностью |
| Плавность траектории | ✗ Низкая | ✓ Высокая |
| Устойчивость | ✗ Средняя | ✓ Высокая |


## Настройка параметров

Основные параметры в коде (`occupancy_grid_navigator.py`):

```python
# Размер сетки
self.grid_resolution = 0.05  # 5см на клетку (уменьши для большей точности)
self.grid_width = 4.0        # 4м ширина (±2м от центра)
self.grid_length = 3.0       # 3м вперёд (увеличь для раннего планирования)

# Пороги обнаружения
self.obstacle_threshold = 0.5   # Начать планирование при препятствии < 0.5м
self.clear_threshold = 1.5      # Путь свободен при > 1.5м

# Стоимости клеток
self.forbidden_cost = 100.0     # За линиями (очень высокая)
self.obstacle_cost = 10.0       # Препятствия

# Скорости
self.avoidance_speed = 0.15     # Скорость при объезде (увеличь для агрессивности)
self.normal_speed = 0.22        # Обычная скорость
self.waypoint_angular_gain = 2.0  # Коэффициент поворота (больше = резче)
```

## Сравнение файлов

**Старый:** `obstacle_avoidance.py` (13KB, ~320 строк)
- Реактивный алгоритм с секторами
- Жёсткая логика для конусов и машин
- Не решает проблему путаницы с линиями

**Новый:** `occupancy_grid_navigator.py` (20KB, ~500 строк)
- Occupancy Grid + A* планирование
- Универсальный подход для любых препятствий
- Полностью учитывает линии и не путает их с конусами

## Тестирование

### Сценарии для проверки:

- [ ] **Конусы на прямой:** Робот должен объезжать конусы и не путать их с линиями
- [ ] **Конус рядом с линией:** Робот должен правильно определить запрещённую зону
- [ ] **Туннель:** Робот должен проезжать туннель без столкновений
- [ ] **Машина на полосе:** Робот должен объехать машину и вернуться на полосу
- [ ] **Несколько конусов подряд:** Робот должен проложить плавный путь
